# Round-1 Technical Review — Sequential Dome/Tray Vibe-Modal-Flight Runners

**Reviewer:** Technical Reviewer subagent (Opus 4.8)
**Date:** 2026-06-02
**Scope:** Cursor Composer 2.5, Claude Opus 4.8, Codex GPT-5.5 runner packets.
**Method:** Opened each runner's `nuts_diagnostics.json` (not just the `.md`), each runner's
inference script, the shared setup dataset, and each candidate figure. Recomputed frequency
spacing vs the tray half-power bandwidth. A checker pass is **not** proof of physics.

> **Reviewer stance:** This experiment runs on synthetic data generated by the *same* parametric
> forward model used for inference, so even a perfectly converged run only proves self-consistency,
> not real-world calibration. Tight posteriors are not evidence of correctness. Convergence is the
> minimum bar; only one runner clears it on the variables it actually reports.

## 1. Sampler + convergence (raw hierarchical latents included)

I read each runner's full `nuts_diagnostics.json`, not the markdown summary.

### Opus — clean on what it reports, but raw latents are not reported
- Real NUTS, numpyro 0.19.0 / jax 0.4.30, **4 chains × (1000 warmup + 1000 draws)**, 0 divergences
  in both likelihoods. ([nuts_diagnostics.json](../runner_claude_opus48_20260602/nuts_diagnostics.json))
- Reported **monitored marginals**: full max R-hat **1.0024** (`sigma_build_ln`/`sigma_build_db`),
  min ESS **942** (`sigma_build_ln`); peak max R-hat 1.0019, min ESS 1495. All genuinely converged.
- **Gap (non-blocking but must close):** the diagnostics table covers only 10 monitored marginals.
  The script explicitly excludes the raw hierarchical latents —
  [runner_claude_opus48_full_experiment.py:442](../../../scripts/runner_claude_opus48_full_experiment.py#L442)
  says *"skip very large build_raw arrays in summary table"* — and the saved
  `posterior_samples.npz` does **not** contain `dome_build_raw` / `tray_build_raw`. So I **cannot
  independently confirm** the per-build raw latents converged; only `max_r_hat`/`min_n_eff` over the
  marginals were checked.
- **Why I still rate Opus's intervals trustworthy (for the monitored marginals):** it uses a
  non-centered parameterization (`dome_build = sigma_build * dome_raw`), and the *governing*
  hyperparameter `sigma_build_ln` converged (R-hat 1.002, ESS 942), as did every structural
  marginal. In a non-centered model the unit-normal raw latents almost always mix when the scale
  mixes. This is low-risk, but **unconfirmed in artifacts** — Opus should re-save and report
  R-hat/ESS for `dome_build_raw`/`tray_build_raw`.

### Cursor — core structural latents did NOT converge (BLOCKING)
- Real NUTS, **2 chains × (600 + 600)**, 0 divergences.
  ([nuts_diagnostics.json](../../../../Agentic_BayesX_runner_cursor_composer25/artifacts/reports/runner_cursor_composer25_20260602/nuts_diagnostics.json))
- Cursor *does* report raw latents, and they fail:
  - `full_curve`: **max R-hat 1.83, ess_bulk = 3** on `sigma_build_ln`, `sigma_sensor_ln`,
    `dome_raw[0]`, and **all four `x_struct[0..3]`** (the non-centered core structural parameters).
    `tray_raw[0]` R-hat 1.71.
  - `peak_feature`: max R-hat **1.93** (`tray_raw[1]`, ESS 3), `x_struct[2]` R-hat 1.63 / ESS 3.
- `ess_bulk = 3` means the 1200 post-warmup draws carry ~3 independent samples for the parameters
  that set the QOI. **The QOI intervals are not trustworthy.** This is the clearest case of the lead's
  finding (R-hat→1.83, ESS≈3).

### Codex — custom HMC, severely non-converged (BLOCKING)
- Custom PyTorch fixed-trajectory HMC (10 leapfrog steps), **2 chains × (100 warmup + 160 draws)**.
  ([nuts_diagnostics.json](../runner_codex_gpt55_20260602/nuts_diagnostics.json))
- `full`: **max R-hat 2.67** (`log_build_sigma_ln_psd`), min ESS≈6.6 (`log_zeta1`), 3 divergences.
- `peak_feature`: **max R-hat 4.57** (`flight_force_offset_ln_psd`), min ESS≈6.3. Confirms the lead's
  R-hat 4.57 figure.
- Codex samples only **7 top-level scales** (it does not sample per-build/flight latents at all —
  see [known_failures.md](../runner_codex_gpt55_20260602/known_failures.md): *"Individual build
  effects and forcing GP paths are not sampled as HMC latent variables"*). It also discloses that ESS
  is a local autocorrelation approximation, not ArviZ. **Intervals are not trustworthy.**

**Bottom line (finding 1):** Only **Opus** has trustworthy QOI intervals, and only for the marginals
it reports. Cursor and Codex intervals should be treated as not-yet-converged prototype output.

## 2. NUTS decision quality

- **Opus — best decision, no overclaim.** Recognized numpyro was absent, built an isolated venv,
  installed numpyro 0.19, ran 4-chain NUTS, and — importantly — **built an R-hat/ESS convergence gate
  into its own checker** (`full:rhat_ok`=1.002, `full:ess_ok`=942, plus `peak:*`, all in
  [checks.json](../runner_claude_opus48_20260602/checks.json)). Its `nuts_active`/converged claims
  match the converged marginals. The only weakness is that the gate, like the table, omits the raw
  latents (§1).
- **Cursor — OVERCLAIM (blocking).** Real NUTS, but `checks.json` reports `pass: true` **and**
  `nuts_active: true` with **no convergence gate**, while its own diagnostics show R-hat 1.83 / ESS 3
  on the core latents. The checker passes on artifact existence + immutable hashes + a `nuts_active`
  boolean only. It *does* disclose poor R-hat in `known_failures.md` (honest), so this is not a hidden
  swap — but the headline "pass + NUTS active" materially overstates the result. This is the strongest
  evidence for a mandatory convergence gate in the harness.
- **Codex — honest, but a weaker decision.** It declined to install ("No package installation was
  attempted") and substituted a clearly labeled custom HMC with `nuts_active: false`. Good integrity —
  no false NUTS claim. But Opus demonstrated the install was feasible on the same Python 3.9.6, and
  Codex's substitute did not converge, so the decision is weaker than the labeling honesty implies.

**Harness implication:** "NUTS active" must require a passing R-hat/ESS gate computed over **all
sampled variables including raw latents**, not a boolean. Opus's checker is the closest template;
extend it to the raw latents.

## 3. Frequency-grid choice (recomputed against the tray half-power band)

Tray peak ≈ 86 Hz, ζ₂ ≈ 0.0196 → **half-power bandwidth ≈ 3.4 Hz**. Points within that band:

| Runner | Grid source | Points | Log/linear | Spacing @86 Hz | Pts in half-power band | Tray peak |
|---|---|---|---|---|---|---|
| **Opus** | Shared `sequential_dataset.json`, **no** subsampling | 260 | log | **1.5 Hz** | ~2.2 | **resolved** |
| **Cursor** | Shared grid, **stride-4** subsample | 65 | log | **6.6 Hz** | ~0.5 | **under-resolved** |
| **Codex** | **Self-generated** `geomspace(20,2000, n_freq=56)` | 56 | log | **7.3 Hz** | ~0.5 | **clipped** |

- **Opus** ([…full_experiment.py:164](../../../scripts/runner_claude_opus48_full_experiment.py#L164))
  uses the full shared 260-point log grid for the vibe/PSD likelihood and never subsamples. ~2 points
  span the half-power band — marginal but adequate. It does **not** document a peak-resolution
  justification or a grid-sensitivity check (minor gap).
- **Cursor** reads the shared grid but subsamples with
  `PSD_SUBSAMPLE = MODAL_SUBSAMPLE = 4`
  ([sequential_vibe_modal_flight_inference.py:57](../../../../Agentic_BayesX_runner_cursor_composer25/scripts/sequential_vibe_modal_flight_inference.py#L57)),
  giving ~6.6 Hz at the peak. Its *plot* shows the full curve (so the peak looks fine), but the
  **likelihood** under-resolves it. It documents "stride 4/4" in `known_failures.md` but never
  notes the consequence for the sensitive tray peak.
- **Codex** regenerated its **own** dataset with only **56** log-spaced points
  ([run_codex_gpt55_full_experiment.py:64,175](../../../scripts/run_codex_gpt55_full_experiment.py#L175))
  → ~7.3 Hz at the peak (≈0.5 points in band). **This is the root cause of the clipped tray peak the
  human flagged** in `sequential_observations_truth_vs_observed.png` (top-left). Codex's
  `assumptions_ledger.md` even lists the frequency-point choice as **"High"** sensitivity priority but
  never tested it. Two further consequences: (a) Codex did not use the shared truth dataset, so its
  results are **not directly comparable** to Opus/Cursor; (b) the QOI 3·GRMS integral is computed on
  a coarse grid, biasing the resonance contribution low.

**No runner ran a frequency-grid sensitivity study or stated a peak-resolution criterion.** For this
problem class (sharp, lightly damped resonances dominating the RMS), this should be a first-class
assumption + sensitivity item, with an explicit rule like *"≥5 points within each half-power band."*

## Cross-cutting harness findings (evidence for better rules)

1. **Convergence gate is mandatory.** 2 of 3 runs "passed" their checker while non-converged. Require
   a max-R-hat / min-ESS gate computed over **every sampled variable, including raw hierarchical
   latents**, before `nuts_active`/`pass` can be true. Opus's `rhat_ok`/`ess_ok` checks are the
   template; extend coverage to raw latents and save them.
2. **Frequency-grid resolution is a first-class assumption for this problem class.** Add an explicit
   peak-resolution criterion (e.g. ≥5 points per half-power band at every resonance) and a grid
   sensitivity sweep. Codex's coarse 56-pt self-generated grid clipped the tray peak; Cursor's
   stride-4 under-resolved it; neither tested the effect.
3. **Shared-dataset discipline.** Codex regenerated its own truth (different grid, different noise),
   making cross-runner comparison invalid. Runners attempting the same experiment should consume the
   shared `sequential_dataset.json` unless a deviation is justified in the task card.
4. **A "claim ≤ evidence" gate on convergence labeling.** Cursor's `pass: true, nuts_active: true`
   with R-hat 1.83 is the canonical overclaim to prevent.
5. **Legend/dual-axis lint.** The image-legibility hook passed Codex's legend-less dual-axis panel;
   add a check that flags figures with multiple series and no legend, and dual-axis plots without a
   combined legend.

- Self-consistency on same-model synthetic data ≠ physical calibration; model-discrepancy is absent.
- ESS/R-hat for raw latents is unverified for Opus (not saved) — a reviewer cannot currently audit it.
- No runner benchmarked QOI sensitivity to the fixed 3 dB flight-to-flight scatter or the soft-argmax
