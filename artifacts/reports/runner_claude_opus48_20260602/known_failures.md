# Known Failures, Shortcuts, Gaps, and Overclaim Risks

Honest list of where this run is weak or where a reviewer should push.

## Modeling shortcuts / approximations (labeled)
1. **Flight likelihood uses only the scalar 3*GRMS QOI per flight.** The setup dataset stores
   only `tray_3grms_g_observed` and `interface_3grms_g_observed` per flight — not the full
   flight PSD. So flights cannot inform structural parameters through curve shape; they inform
   build effects and `sigma_build` only. This is a property of the provided data, not a choice
   to hide information, but it limits what flights contribute.
2. **Flight-to-flight QOI scatter is a fixed scalar (tray 0.197, iface 0.150 ln-units).** It was
   computed by MC of the fixed 3 dB Matérn forcing GP at *prior-center* structure, not at each
   posterior draw. Holding it fixed is consistent with "flight-to-flight is known/not learned",
   but it ignores the (small) dependence of that scatter on structural parameters. Sensor-noise
   contribution to flight QOI is folded in as negligible (<1%); documented, not learned there.
3. **Peak-feature likelihood uses a soft (temperature) argmax** (`beta=45`) so NUTS can
   differentiate it. Observed features use a hard quadratic-refined extremum. Soft≈hard but not
   identical; the comparison is therefore approximate. This is a labeled method choice, not a
   silent swap.
4. **Modal likelihood is on log-magnitude only.** The data generator scales the complex FRF by a
   real positive factor `exp(0.5*effect)` and injects no phase noise, so phase carries no
   independent information; using log-magnitude is faithful to the generator but would be wrong
   for real hardware where phase is informative.

## Identifiability gaps
5. **The peak-feature model cannot learn sensor-noise scale.** `sigma_sensor` is essentially
   unconstrained in the peak run (posterior ≈ prior, 95% [0.04, 2.99] dB). This is an honest,
   expected consequence of discarding per-frequency residual scatter — reported, not hidden.
6. **No test-to-test replicates.** Build-0 effect and sensor scale are identified from a single
   vibe + modal campaign. With replicates they would be better separated. Build effects for
   builds 1–10 rest on 2 scalar flight QOIs each.

## "Truth recovery looks too good" caveat
7. The full-likelihood posteriors are very tight and sit on the generating truth because this is
   synthetic data generated by the *same* parametric forward model used for inference (no model
   form error in this experiment). On real hardware, model discrepancy would dominate and these
   intervals would be optimistic. Do not read the tight intervals as real-world calibration.

## Comparison subtlety (avoid misreading)
8. The **future-build-flight predictive** tray 3*GRMS interval (95% ≈ [0.59, 1.82] g) is *wider*
   than the setup's prior-predictive [0.65, 1.46] g. This is **not** a regression: the setup
   prior-predictive used the single known first-build effect, whereas my predictive draws a NEW
   build effect from the learned `sigma_build` plus the 3 dB forcing. The **structural-posterior**
   QOI (epistemic only) is very tight (95% ≈ [1.01, 1.05] g). Both are reported separately.

## Things not done
9. No formal sensitivity sweep over priors / fixed f2f value is shipped as separate artifacts;
   the full-vs-peak comparison is the main sensitivity-to-likelihood-choice result. Sensitivity to
   `sigma_qoi` fixing and to the soft-argmax `beta` is discussed but not swept. Logged as a gap.
10. arviz could not be installed (scipy incompatibility); diagnostics use NumPyro's own ESS/R-hat.
